# Автообновление CoolSnesh Downloads

## Как работает

- При запуске приложения проверяется публичный GitHub Releases API репозитория `crazysnesh1/CoolSnesh-Downloads`.
- Дополнительно проверка повторяется раз в 6 часов, пока приложение открыто. Кнопка «Проверить версии» также запускает тихую проверку версии самого загрузчика.
- Если опубликован стабильный релиз новее текущей версии, рядом с названием в шапке появляется кнопка с номером версии. По нажатию пользователь видит текущую и новую версии и заметки релиза.
- Приложение загружает `CoolSnesh Downloads.exe` и `CoolSneshDownloads-win-x64.exe.sha256`, проверяет SHA-256 и только после этого запускает временный помощник PowerShell.
- Помощник ждёт завершения приложения, создаёт резервную копию, заменяет EXE и запускает новую версию. Если запуск новой версии сразу завершается с ошибкой, выполняется попытка отката.
- Резервные копии хранятся в `%LOCALAPPDATA%\CoolSneshDownloads\UpdateBackups` до 30 дней. Журнал процесса обновления: `%APPDATA%\CoolSneshDownloads\logs\updater.log`.
- Если каталог приложения защищён, помощник запрашивает UAC. Для обычного пользовательского размещения, например в `%LOCALAPPDATA%` или папке пользователя, повышение прав обычно не требуется.

## Требуемые файлы в GitHub Release

Release workflow уже должен прикреплять эти файлы:

- `CoolSnesh Downloads.exe`
- `CoolSneshDownloads-win-x64.exe.sha256`
- `CoolSneshDownloads-win-x64.zip`
- `CoolSneshDownloads-win-x64.zip.sha256`

Имя EXE и checksum-файла должно совпадать с указанным выше. Самообновление доступно из опубликованного EXE с именем `CoolSnesh Downloads.exe`; запуск через `dotnet run`/`dotnet.exe` намеренно не обновляет файл SDK.

## Первый запуск механизма

Старые сборки, в которых ещё нет `AppUpdateService`, не умеют получать уведомление и автоматически обновляться. Первую сборку с этим механизмом нужно скачать вручную из GitHub Release. После неё новые стабильные релизы будут обнаруживаться автоматически.

Проверка использует только публичный `releases/latest` и не требует GitHub-токена. Если релиз ещё не опубликован, приложение не покажет уведомление и продолжит работать как обычно. При сетевой ошибке ранее обнаруженное обновление не скрывается.

## Проверки

Добавлены юнит-тесты для обнаружения новой версии, отсутствия обновления при совпадающих версиях, отклонения чужого хоста и отсутствия checksum-файла. На Windows проверь сценарий на пользовательской папке: опубликуй более высокую версию, запусти прежний EXE, нажми кнопку обновления и убедись, что SHA-256 проверен, приложение закрылось и открылось снова.


## Исправление сравнения версий релиза

Сервис сравнивает `currentVersion` с `tag_name`: отрицательный результат означает, что доступен более новый релиз; ноль — версии совпадают; положительный результат означает, что установленная версия новее последнего стабильного релиза. Добавлен тест на последний случай.
